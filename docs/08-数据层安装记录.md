### ⚠️ 切库时踩的坑：MySQL 8.0 不支持 `NULLS LAST`

切库当天 `/api/v1/campaigns` 直接 500：

```
pymysql.err.ProgrammingError: (1064, "...near 'NULLS LAST) AS anon_1'")
```

根因是排序写成了 `AdCampaign.roi.asc().nulls_last()`：

| 数据库 | 支持 `ORDER BY x NULLS LAST` 吗 |
| --- | --- |
| SQLite | ✅ 3.30+ 开始支持 |
| MySQL 8.0 | ❌ **不支持**（MariaDB 才支持） |

修法是写成显式排序键，不依赖任何方言特性：

```python
from sqlalchemy import case

null_rank = case((AdCampaign.roi.is_(None), 1), else_=0)
stmt = stmt.order_by(null_rank, AdCampaign.roi.asc())
```

**为什么单元测试没拦住**：单元测试跑的是 SQLite，和开发库用同一个方言 ——
**测试和开发同源，就永远测不出方言差异**。
所以新增了 `tests/test_api_mysql.py`：拿真 MySQL 把所有只读接口打一遍，
没有 MySQL 时自动跳过（同 `test_gateway_redis.py` 的思路）。

验证方法：把 `nulls_last()` 改回去，那个参数化用例立刻变红，报错一字不差。

**顺带自查过的其他方言差异**（都没问题）：
`func.date()` 分组、`case()` 条件聚合、`outer join`、`func.count(distinct ...)`。

### 怎么重新初始化

```powershell
cd platform\deploy\scripts
.\init-mysql.ps1
```

脚本会：

1. 交互式询问 root 密码（**只在本机终端内使用**）
2. 建库 `fashionops`（utf8mb4）
3. 生成随机应用密码，创建 `fashionops@localhost`，只授权这一个库
4. 把连接信息写进 `platform\.env`
5. 用应用账号回连自测

密码处理方式（值得说明，因为这是常见的安全疏漏）：

- root 密码通过**临时 option file** 传给 `mysql.exe`，不出现在命令行参数里
  （否则同机器上任何进程都能从进程列表里 `Get-Process` 读到）
- 应用密码用 `RandomNumberGenerator` 生成，只写进 `.env`
- 脚本全程**不打印任何密码**
- 临时文件在 `finally` 块里删除

### ⚠️ 踩坑：msys2 版 Redis 不认 Windows 绝对路径

这是装 Redis 时踩到的坑，值得单独记一笔。

**现象**：

```powershell
D:\develop\redis\redis-server.exe "c:\path\to\redis.conf"
# Fatal error, can't open config file '/develop/redis/c:\path\to\redis.conf'
```

**原因**：msys2 编译出来的是 Unix 语义程序，只把以 `/` 开头的路径当作绝对路径。
`c:\...` 不以 `/` 开头，所以 Redis 认为它是**相对路径**，拼到当前工作目录后面，
就成了 `/develop/redis/c:\path\to\redis.conf`。

**另一个现象**：命令行选项和配置文件混用时还会报 `wrong number of arguments`：

```
>>> 'dir "D:/develop" "c:/path/redis.conf"'   wrong number of arguments
```

因为 Redis 在参数不以 `--` 开头时把 `argv[1]` 当配置文件；混用 `--dir` 时，
解析器会把后面的值拼到同一行。

**解法**（已实现在 `services.ps1` 里）：

1. 配置文件用**相对文件名**启动，工作目录设为 Redis 安装目录
2. 配置里的 `dir` 用相对路径 `./data`
3. 日志不写绝对路径，改用 `Start-Process -RedirectStandardOutput` 重定向

```powershell
# 实际执行的等价命令
cd D:\develop\redis
.\redis-server.exe redis.local.conf          # 命令里完全不出现绝对路径
```

## 5. ⚠️ 踩坑：系统代理导致本地服务返回 502

**这是本次排查花时间最多、也最值得记下来的问题。**

### 现象

后端 `/health` 一直报 Qdrant 不可用：

```json
{"name":"qdrant","ok":false,"detail":"HTTPStatusError: Server error '502 Bad Gateway'
 for url 'http://127.0.0.1:6333/healthz'"}
```

但是：

- 用 `curl.exe http://127.0.0.1:6333/healthz` → **200 healthz check passed**
- Qdrant 进程活着，端口开着，日志里一点异常都没有
- 连 `qdrant-client`（官方客户端）也报 502

### 根因

这台机器上设了**系统代理**（Clash / VPN / 抓包工具之类）。
在 Windows 上，`httpx` / `requests` 在 `trust_env=True`（默认值）时，
会通过 `urllib.request.getproxies()` 去读**注册表里的 Internet Settings**，
然后把 `http://127.0.0.1:6333` 这个**本机地址也丢给代理**。
代理当然不认识本地 Qdrant，于是回一个 `502 Bad Gateway`。

对照验证：

```python
httpx.get('http://127.0.0.1:6333/healthz').status_code                   # 502
httpx.get('http://127.0.0.1:6333/healthz', trust_env=False).status_code  # 200  ✅
```

### 为什么迷惑

1. `curl` 不读系统代理，所以用 curl 测一切正常
2. **请求根本没到 Qdrant**，所以 Qdrant 日志里什么都没有
3. 错误信息只有一句 "502 Bad Gateway"，第一反应一定是"Qdrant 挂了"

### 修法

已实现为 `platform/src/fashionops/net.py`，在配置模块加载时自动执行：

把 `localhost,127.0.0.1,::1,0.0.0.0` 并入 `NO_PROXY` 环境变量。

**只影响本地服务**；访问 `api.deepseek.com` 这类外网地址仍然照常走代理，
不会把"需要代理才能上网"的环境弄坏。

`/health` 的返回里也带上了 `no_proxy` 字段，下次同类问题一眼可见。

## 7. Docker —— 未安装，为什么现在不需要

### 状态

**未安装**。Docker Desktop 的安装需要管理员权限并且要重启机器，
这一步需要你自己执行，我无法代跑。

### 但当前架构不依赖 Docker

规划文档 §9 讨论过这件事。结论是：架构图上的组件名是**参考实现**，不是硬性要求。
每一层都有等价替代，而且都已就位：

| 架构图要求 | 职责 | 本机方案 | 状态 |
| --- | --- | --- | --- |
| PostgreSQL | 业务数据 | **MySQL 8.0**（本机已有实例） | ✅ |
| pgvector | 向量检索 | **Qdrant 1.19.1** | ✅ |
| Redis | 会话状态 | **Redis 8.10.1** | ✅ |
| MinIO | 对象存储 | 本地文件系统（`StorageBackend` 抽象，可切） | ✅ |

**Qdrant 其实比 pgvector 更适合这个项目** —— 它是一个独立的向量数据库，
支持 payload 过滤、稀疏向量（混合检索用）、内建重排，讲 RAG 时能展开的细节更多。

### 代码层面已经为 Docker 留好口子

换回 Docker 只需要改配置，不用动业务代码：

- 关系库：改 `.env` 的 `FASHIONOPS_DB_HOST` 指向新实例，或直接给 `FASHIONOPS_DATABASE_URL`
- 向量库：`VectorStore` 抽象已留，换 `pgvector` 只加一个适配器类
- 对象存储：`StorageBackend` 抽象已留，换 MinIO 只加一个适配器类

### 将来要装的话

1. 下载 Docker Desktop for Windows（AMD64）
2. 安装（勾选 WSL2 backend），**重启机器**
3. 验证 `docker --version` && `docker compose version`

到阶段 3 如果还想体验真实的 PostgreSQL + pgvector，
`deploy/docker-compose.yml` 也会一并准备好，装完直接 `docker compose up` 即可。

## 9. 常见故障速查

| 现象 | 大概率原因 | 怎么办 |
| --- | --- | --- |
| `/health` 里 database `ok=false` | MySQL80 服务没启动 / `.env` 里没填 host | `net start MySQL80`；跑 `init-mysql.ps1` |
| `/health` 里 redis `ok=false` | Redis 没启动 | `.\services.ps1 start -Only redis` |
| `/health` 里 qdrant `ok=false`，但 curl 正常 | **系统代理拦截了 Python 请求** | 见 §5；确认 `.env` 里没有奇怪的 proxy 变量，`fashionops/net.py` 会自动处理 |
| 访问接口报 503 且提示数据库不可用 | 表还没建 | `uv run fashionops-db init && uv run fashionops-seed` |
| `redis-server.exe` 报 `can't open config file` | 路径写成了 Windows 绝对路径 | 见 §3 的踩坑说明，用相对路径启动 |
| `.ps1` 脚本报"数组索引表达式丢失或无效" | PowerShell 5.1 把无 BOM 的 UTF-8 按 GBK 读了 | 把脚本存成**带 BOM** 的 UTF-8 |
| Python 脚本打印中文报 `UnicodeEncodeError` | Windows 控制台默认 GBK | 设 `$env:PYTHONIOENCODING="utf-8"`，或脚本内 `sys.stdout.reconfigure(encoding="utf-8")` |
| MySQL 连接串报解析错误 | 密码里有 `@` / `/` 等 URL 保留字符 | 代码已用 `quote_plus` 处理；手写连接串时要自己转义 |
| 早上第一批请求报 `MySQL server has gone away` | 连接池里的连接被服务端 `wait_timeout` 掐断了 | 引擎已开 `pool_pre_ping=True` + `pool_recycle=1800` |
| 接口 500，日志里是 `1064 ... syntax to use near 'NULLS LAST'` | 用了 MySQL 不支持的 `NULLS LAST` 排序 | 见 §2 的踩坑说明，改用 `case()` 显式排序键 |
| `uv sync` 后 `ruff` / `pytest` 找不到了 | 没带 `--all-extras`，dev 依赖被卸掉了 | `uv sync --all-extras` |
| 改了 `.env` 但应用行为没变 | 进程启动时就读完配置了，不会重载 | 重启 API 进程 |

# 2026 年 Agent 岗「眼前一亮」技术栈与开源项目

> 调研时间：2026-09-11　　目标：用新技术做出有区分度的简历项目
> 核实标准：协议级标准 / 有论文或基准背书 / 能落到自己代码里

---

## 一、先定标准：什么样的技术能让人抬头

三个特征，占两个就值得写进简历：

1. **协议级 / 标准级** —— 不是某个厂的私有 SDK，而是行业在收敛的标准（MCP、A2A、Agent Skills spec、OTel GenAI semconv）
2. **有论文或公开基准背书** —— 面试官可以自己去查（Graphiti 论文、τ³-bench leaderboard）
3. **能落到你自己代码里** —— 你能讲清"我怎么用的、踩了什么坑"，而不是只会背概念

| --- | --- |
| 仓库 | `PrefectHQ/fastmcp`（原 jlowin/fastmcp） |
| 语言/协议 | **Python 100%** / **Apache-2.0** |
| 版本 | v4.0.3（上周），极活跃 |
| 分量 | FastMCP 1.0 在 2024 年被并入**官方 MCP Python SDK**；当前日下载百万级，**约 70% 的 MCP server（全语言）基于它**；13k 项目依赖 |

**面试话术**：

### 2️⃣ A2A 协议 —— `a2aproject/A2A` ⭐25.7k

| 项 | 内容 |
| --- | --- |
| 协议 | **Apache-2.0**，**Linux Foundation 项目**（Google 捐赠） |
| 版本 | v1.0.1，13 小时前仍有提交 |
| SDK | Python `pip install a2a-sdk`（另有 Go/JS/Java/.NET/Rust） |
| 配套 | DeepLearning.AI 有官方课程 |

**核心机制**：JSON-RPC 2.0 over HTTP(S)；**Agent Card 做能力发现**；同步 / SSE 流式 / 异步推送三种交互；支持文本、文件、结构化 JSON；内置企业级鉴权设计。

**关键理解（面试必答）**：
> **MCP 管 agent ↔ 工具；A2A 管 agent ↔ agent。** 两者互补，不是竞争。

**二次开发**：把单体办公 Agent 拆成「会议 Agent」「文档 Agent」「数据分析 Agent」三个 A2A server，通过 Agent Card 互相发现与协作。

**面试话术**：
> "用 A2A 把单体 Agent 拆成 3 个可独立部署、独立扩缩容的 Agent 服务，通过 Agent Card 做能力发现，任务通过 JSON-RPC 与 SSE 流式回传。"

### 3️⃣ Agent Skills 标准 —— `anthropics/skills` ⭐175.7k

| 项 | 内容 |
| --- | --- |
| Stars | **175.7k**（这个量级说明热度） |
| 内容 | `spec/` = **Agent Skills 规范**；`template/`；示例 skills |
| 标准站 | `agentskills.io` |
| 语言 | Python 85.6% |

**渐进式披露（Progressive Disclosure）** 是核心思想：skill 平时只暴露 name + description，模型需要时才把完整 `SKILL.md` 注入上下文 —— 这是**省 token 的关键工程手法**。

**⚠️ 许可证陷阱（必须知道）**：
`skills/docx`、`skills/pdf`、`skills/pptx`、`skills/xlsx` 这四个文档 skill 是
**source-available，不是开源**（Anthropic 明确说明）。它们驱动 Claude 的文档能力，仅供开发者参考。
其余多数 skill 是 Apache-2.0。**别把 docx/pdf/pptx/xlsx 直接抄进商业项目。**

**二次开发**：按 spec 写办公 skills，并自研渐进加载调度器。

**面试话术**：
> "按 Agent Skills 规范实现技能层，用渐进式加载把技能描述与技能正文分离，只在命中时注入完整指令，上下文 token 下降 XX%。"

### 4️⃣ 时序知识图谱记忆 —— Graphiti ⭐30.8k

| 项 | 内容 |
| --- | --- |
| 仓库 | `getzep/graphiti` |
| 语言/协议 | **Python 99.3%** / **Apache-2.0** |
| 版本 | v0.30.2（3 天前），活跃 |
| 论文 | **arXiv 2501.13956**（Zep: A Temporal Knowledge Graph Architecture） |
| 生态 | 自带 **MCP server** + FastAPI REST 服务；**官方有 LangGraph 集成指南** |
| 后端 | Neo4j 5.26 / FalkorDB / Amazon Neptune（Kuzu 已废弃） |

**核心能力（和普通向量 RAG 的本质区别）**：
- **双时间有效性窗口**：事实变更时是**标记失效**，不是删除 —— 可以查"现在的真相"，也可以查"某时刻的真相"
- **Episode 溯源**：每个实体与关系都能追溯到产生它的原始数据
- **增量构建**：新数据立即写入，无需全图重算
- **混合检索**：语义 + BM25 + 图遍历，亚秒级延迟

**文档里有 Graphiti vs GraphRAG 对比表**，是很好的面试素材（GraphRAG 是批处理 + 社区摘要；Graphiti 是增量 + 时间有效性）。

**二次开发**：把 DeerFlow 的记忆后端换成 Graphiti，做「企业制度/客户信息随时间变化」的问答。

**面试话术**：
> "用时序知识图谱替换扁平向量记忆，事实带有效性窗口，解决新旧信息冲突与时效性问题；检索用向量+BM25+图遍历混合召回，准确率 X→Y。"

### 5️⃣ 持久化执行 —— DBOS Transact ⭐1.6k

| 项 | 内容 |
| --- | --- |
| 仓库 | `dbos-inc/dbos-transact-py` |
| 语言/协议 | **Python 100%** / **MIT** |
| 版本 | v2.31.1（3 天前），活跃 |
| 亮点 | 仓库里有 **chaos-tests** 目录（混沌测试） |

**机制**：把函数用 `@DBOS.workflow()` / `@DBOS.step()` 装饰，状态 checkpoint 到 **Postgres**，进程崩溃后在重启时**从最后一个完成的 step 继续**，不需要外部编排服务。还提供持久队列、持久调度、持久通知、精确一次事件处理。

README 明确点名适用场景：**"Operating an AI agent, or any application that relies on unreliable or non-deterministic APIs."**

**为什么这是"信息差"**：LLM 调用天然不可靠、长任务天然易断。大部分候选人的 Agent 跑挂了就从第一步重来。

**二次开发**：让"跑 2 小时的月报生成"在服务重启后增量续跑。

**面试话术**：
> "引入持久化执行，把 Agent 的模型调用与工具调用包装为可 checkpoint 的 step；长任务崩溃恢复从全量重跑降为增量续跑，平均恢复成本下降 XX%。"

### 7️⃣ Agent 评测基准 —— τ³-bench ⭐

⚠️ **重要修正**：`sierra-research/tau-bench`（⭐1.4k, MIT）**已弃用**。README 明确警告：

> "The tasks in this repo are not updated. This repository contains outdated versions of the airline and retail tasks. Please use **τ³-bench** for the latest fixed tasks and new domains."

**正确仓库**：`sierra-research/tau2-bench`（即 τ³-bench）
- 新增 **banking 域** + **voice 评测模态**，并修复了 airline / retail 任务

**为什么值得用**：
- 作者包括 **Shunyu Yao**（ReAct、Tree of Thoughts 作者）与 **Karthik Narasimhan**
- 它模拟 **「用户 ↔ Agent ↔ 工具」三方动态多轮对话**，比 GAIA 那种单轮问答更贴近真实办公场景
- 自带 **`auto_error_identification.py`**：自动**故障归因**（user / agent / environment）+ **故障分类**（`used_wrong_tool`、`used_wrong_tool_argument`、`took_unintended_action`、`goal_partially_completed`）
- 多轮用户模拟器策略：`llm` / `react` / `verify` / `reflection`

**二次开发**：把自己的办公 Agent 跑一遍，出 `pass^k` 分数 + 错误归因报告。

**面试话术**：
> "在 τ³-bench 上评测自研办公 Agent，用自动错误归因定位到 42% 的失败源于工具参数错误，针对性补了参数校验与 tool schema 约束，pass^1 从 X 提升到 Y。"

**这是简历上最能打的一条** —— 因为 90% 的候选人只能说出"我做了个 Demo"，说不出数字。

### 8️⃣ 新一代类型安全框架 —— Pydantic AI ⭐19.9k

| 项 | 内容 |
| --- | --- |
| 仓库 | `pydantic/pydantic-ai` |
| 语言/协议 | **Python 99.8%** / **MIT** |
| 版本 | v2.42.0（2026-09-08），595 贡献者，4.6k 项目依赖 |
| 团队 | Pydantic 官方 —— OpenAI SDK / Anthropic SDK / Google ADK / LangChain 的校验层都是 Pydantic |

**为什么"新"**：
- **Capabilities 原语**：把 tools + instructions + hooks + model settings 打包成一个可复用单元；支持 `defer_loading=True` **按需加载**（等价于 skill 机制）

- **OTel 原生埋点** + Pydantic Logfire
- **Pydantic Evals**："像 pytest 测代码一样测 Agent 行为"
- **Pydantic Graph**：带类型推导的图编排（LangGraph 的现代替代思路）
- **原生 Realtime Voice**：OpenAI Realtime / Gemini Live / Azure / xAI Grok Voice
- **AG-UI / Vercel AI 事件流**：直接接前端
- 还有 Pydantic AI Harness：memory / sub-agents / context compaction / coder agent

**二次开发**：用 Pydantic AI 重写核心 Agent 层；或用它的 Evals 做评测模块。

**面试话术**：
> "用 Pydantic AI 的 Capability 原语重构工具层，把散落的工具、指令、钩子收敛为可复用、可组合的单元；用 Pydantic Evals 把 Agent 行为纳入 CI。"

## 三、推荐组合（别全上）

**核心原则**：选 2-3 个做深，每个能讲 15 分钟。全上 = 全浅。

### 必上（差异化最大，投入产出比最高）

| 技术 | 为什么必上 | 工作量 |
| --- | --- | --- |
| **MCP server 开发** | 写法简单，但能让面试官立刻确认"真做过" | 2-3 天 |
| **τ³-bench 评测 + 错误归因** | 产出数字，简历上最硬 | 3-5 天 |
| **OTel 全链路追踪** | 企业开发的标准动作，面试常问 | 2 天 |

### 进阶（挑一个做深，讲架构深度）

| 技术 | 适合什么方向 |
| --- | --- |
| **A2A 拆分多 Agent 服务** | 想讲架构设计、服务拆分、分布式协作 |
| **Graphiti 时序记忆** | 想讲记忆/RAG/知识图谱，走"效果优化"路线 |
| **持久化执行** | 想讲工程可靠性、崩溃恢复、状态机 |

### 框架层怎么选（不冲突）

```
DeerFlow（LangGraph 内核）  ← 基座：编排 / 沙箱 / 渠道 / 前端 / RBAC
        +
Pydantic AI                 ← 自研模块：类型安全的核心 Agent 与评测
        +
FastMCP                     ← 工具层：3 个 MCP server
        +
Graphiti                    ← 记忆层：时序知识图谱
        +
OpenLLMetry                 ← 观测层：OTel 埋点
```

它们通过协议（MCP / A2A）与标准（OTel / Agent Skills）解耦，不互相绑定 —— 这本身就是个好架构故事。

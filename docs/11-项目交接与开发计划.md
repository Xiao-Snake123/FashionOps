## 1. 这是什么

**服装电商多 Agent 运营中台。** 一句话：*用自然语言交办一件运营的事，系统自己拆成多个 Agent 步骤跑完，遇到需要人拍板的动作就停下来等你确认。*

```
你输入：「帮我选 3 款秋季女装，再出一份近 30 天的经营分析报表发给 ops@example.com」
          ↓
   模型拆成一张 DAG（有依赖关系的步骤图）
          ↓
   selection Agent 挑款 → analytics Agent 聚合数据 → 生成 xlsx
          ↓
  ⏸ 停下来等人确认（因为下一步要**往外发邮件**，收不回来）
          ↓
   你点「批准」→ notification Agent 过四层闸门 → 投递
          ↓
   全程 SSE 实时推给前端，不用刷页面；结果落库、产物可下载
```

**它不是一个 demo。** 判断依据是这些**真实存在**的东西：

| | 状态 |
| --- | --- |
| 真实 MySQL（23 张表）+ Redis + Qdrant，不是内存模拟 | ✅ |
| 数据库迁移（Alembic，可升降级） | ✅ |
| 真实登录鉴权（argon2id + JWT + RBAC + 审计） | ✅ 2026-09-16 新增 |
| 真实发过邮件（QQ SMTP，走完整网关链路） | ✅ |
| 真实向量检索（智谱 embedding-2 → Qdrant，语义召回有效） | ✅ |
| 结构化日志、配置体检、请求 ID 贯穿 | ✅ |
| 自动化测试 **546** 项 | ✅ |
| **多机部署 / 任务队列持久化 / 可观测性** | ❌ **未做**（见 §5） |

**规模**：后端 22,013 行（75 个文件）· 测试 8,040 行 · 前端 3,564 行。

### 2.2 三个"看起来做了、其实没做"的地方（必须知道）

1. **`ad_campaigns`（12 行，含 3 个亏损计划）、`tickets`（60 行，含 14 条升级）、
   `kb_articles`（17 行）这三张表的数据，前端能看到，但没有任何 Agent 会去读它**。
   它们是为规划中的链路 ②③ 准备的数据，现在只是"有数据"。

2. **只有 6+2 个工具，而且全是读侧。**
   系统目前**不能改变外部世界**（不能上架、不能改预算、不能回工单）。
   `mail.send` 是唯一的写动作，而它默认被闸门拦着。

3. **`ModelRouter` 类写了，但没有任何 Agent 在用** —— 模型路由是规划里的降本手段，
   现在实际是单模型跑到底。

## 4. 一次任务的完整生命周期（读懂这条就懂了大半）

```
① 前端 POST /api/v1/tasks  {user_request}
      ↓ 需要 task:submit 权限
② submit_task():
      · _create_task_row()  → **先落库（status=pending）再返回**
      · effective_scopes()  → 用户权限 ∩ Agent 权限集   ← 防越权的关键
      · record_audit()      → 谁、什么时候、提交了什么
      · 丢进线程池（⚠ 进程内，重启会丢 —— 见 §5 P1）
      ↓
③ build_runner() 组装 TaskRunner（网关 + 模型 + checkpointer）
      ↓
④ planner：模型出 DAG → **代码校验**（环、重复、未知依赖…）→ 不合法就关键词兜底
      ↓
⑤ orchestrator：StateGraph 按依赖顺序跑各节点
      · 每个节点通过网关调工具（限流/熔断/重试/幂等/审计全在这里）
      · 每个节点落一条 agent_runs（token 与成本也算出来）
      ↓
⑥ 到 approval_required 的步骤 → interrupt() 中断 → status=waiting_approval
      · 状态存进 checkpointer（Redis，降级 SQLite）
      ↓
⑦ 前端 SSE 实时收到 approval_required 事件 → 弹常驻审批横幅
      ↓
⑧ POST /{task_no}/approve {approved, reason}
      · 需要 task:approve 权限
      · **审批人取自令牌**，前端无法伪造
      · 落 tasks.approved_by / approved_at / approval_reason + 审计
      ↓
⑨ 从断点续跑 → notification 节点 → 过四层闸门 → 真发或拦下（**放行和被拦都落库**）
      ↓
⑩ finalize：产物写 assets 表，result.artifacts 带 url；status=succeeded
```

### 4.1 贯串全局的三条原则（面试时最值得讲的）

**① 代码出数字和告警，模型只写解读。**
阈值判定、严重程度分级一律在 Python 里（`analytics_rules.py`），
schema 里干脆**不放** severity 字段 —— 模型就无从乱填。
原因：实测 `glm-4-flash` 对"退货率 > 30% 是 critical"这条 prompt，
会把 14.69% 也标成 critical。**任何"算不算问题"的判断都别问模型。**

**② 所有外部调用收口到网关。**
工具不是"便于复用"，是**边界上必须有治理**。绕过治理的入口只要存在一个，
治理就等于没有。

**③ 记录失败不影响业务，但必须配一个计数器。**
`recorder` 吞掉写入异常是对的（不该因为记不上日志就让任务失败），
但 `_safe` 吞异常时曾经掩盖过"事件被静默丢弃"的真 bug。
所以任何 fail-safe 都配一个可观测的计数（`write_failures`、`AUDIT_WRITE_FAILURES`）。

## 6. 埋着的坑（都是真实踩过的，不看会重复踩）

完整版在 `docs/06-开发日志.md`（按时间）和项目长期记忆里（按主题）。
这里列**最容易再踩**的几条：

### 6.1 环境 / 工具

| 坑 | 症状 | 处理 |
| --- | --- | --- |
| **系统代理会让 Python 连不上本地服务** | httpx 请求 `127.0.0.1:6333` 返 **502**，但 `curl.exe` 同一地址 200 | 见 `net.py`。**"curl 正常、Python 报错"的网络问题先怀疑代理** |
| **`alembic.ini` 必须是纯 ASCII** | 中文 → `UnicodeDecodeError: 'gbk'`，**连 `--help` 都跑不了**。`PYTHONUTF8=1` 救不了 | 中文说明写到 `migrations/README.md` |
| **PowerShell `$env:X=""` 是删除变量，不是设为空** | 想用空值覆盖 `.env` 不生效；而且变量会残留到后续命令 | 先 `Remove-Item Env:FASHIONOPS_*`，并打印 `settings.sqlalchemy_url` 确认 |
| **PowerShell 的 `Get-Content`/`Set-Content` 会把 UTF-8 文件重编码搞坏** | 中文全变乱码，文件不可恢复 | **改文件只用编辑工具**，不要用 PowerShell 做文本替换 |
| **Windows 控制台编码三个独立开关** | `chcp` / `[Console]::OutputEncoding` / `PYTHONIOENCODING` 各管一段 | 要么三个都设，要么直接写 UTF-8 文件再读 |
| **改完 `.env` 必须重启 API** | 配置是 `lru_cache` 单例 | 已经踩过两次 |

### 6.2 数据库

| 坑 | 说明 |
| --- | --- |
| **MySQL 的 DDL 不支持事务回滚** | 迁移失败会留下半完成状态，而 `alembic_version` 停在旧版本 → **"版本号说已是最新、实际库是坏的"**。铁律：大 DDL 前先备份，先 `upgrade head --sql` 人工看 |
| **`drop_index` 在 `drop_table` 之前会报 errno 1553** | MySQL 外键**复用同名索引**。**SQLite 上完全看不出来**（它是重建整表）。已加静态检查 + 检查器自身的牙齿测试 |
| **`ORDER BY x NULLS LAST` 是 SQLite 特有能力** | MySQL 8.0 报 1064。曾在 `/api/v1/campaigns` 上炸过。跨方言测试就是为这个建立的 |
| **测试库和开发库同源 = 方言盲区** | 单测跑 SQLite、开发也用 SQLite 时永远测不出差异。所以有 `test_api_mysql.py` 拿真 MySQL 打全部接口 |

### 6.3 认证（本轮新增的坑）

| 坑 | 说明 |
| --- | --- |
| **朴素 UTC + `.timestamp()` = 时区 bug** | `utcnow()` 返回朴素时间但表示 UTC，而 `.timestamp()` 按**本地时区**解释。东八区下 `exp` 比真实时间早 8 小时 → **登录返回 200 拿到 token，下一个请求立刻 401 "登录已过期"**。在 UTC 容器里完全不可见。修复：`tokens.to_epoch()` / `from_epoch()`，**全模块必须走这两个函数** |
| **`get_db` 不 commit 会静默丢数据** | 登录落的 refresh token、审批人字段、审计记录全部被回滚，而接口都返回 200 → "登录后第一次刷新就 401"、"谁批准了"查不到。修复：`get_db` 改成单元工作语义（成功后 commit） |
| **重放检测的检查顺序** | 轮换时同时写 `revoked_at` 和 `replaced_by_id`。先判 `revoked_at` 的话**重放永远被归类成"已登出"，检测永不触发** —— 而它是发现 token 泄漏的唯一信号 |
| **覆盖 `get_db` 依赖的测试会重写事务边界** | 测试替身不该自己重写被替对象的职责。改成只替换**会话工厂**（patch `get_settings`），真实事务边界一行不改地跑 |
| **两处 settings 来源 → 引擎单例被错误的一份占住** | `main.py` 曾把 `config.get_settings()` 的结果传进 `get_engine(settings_)`，而 `db.base` 用自己那份 `get_settings`。测试里只 patch 一处时，**应用连上了开发用的 MySQL 而测试以为在连临时 SQLite**，表现只是"数据不对"、不报错。修复：**一个东西只能有一个获取途径**，`get_engine()` 不传参 |
| **FastAPI 新版 `app.routes` 拿不到子路由** | 被包成 `_IncludedRouter`，子路由藏在 `original_router.routes` 里。**扫不到路由的"鉴权覆盖检查"会静静地全绿** —— 假绿的覆盖检查比没有更危险 |
| **SSE 不能用自定义请求头** | 原生 `EventSource` 不支持。所以 token 只能走 `?token=`（且只传 30 分钟过期的 access token，绝不传 refresh）。这是权衡不是最佳实践 |
| **401 与 403 必须分开** | 前端靠它决定"跳登录页"还是"显示无权限"。混用会让用户看到"请重新登录"，登录完还是不行 |
| **并发 401 会触发多次 refresh → 触发重放检测把人踢下线** | 刷新是**轮换**的，第二次拿的是已被替换的旧 token。必须做单飞（`api.ts` 的 `refreshInFlight`）。**手工点页面几乎测不出来** |

### 6.4 模型 / Agent

| 坑 | 说明 |
| --- | --- |
| **模型会忽略 prompt 里的数值阈值** | 实测对 14.69% 照样标 critical。阈值判定一律交代码 |
| **小样本指标不能按阈值告警** | 3 单退 1 单 = 33%，按阈值算 critical，实际是噪声。分组订单数 < 20 只报"样本不足" |
| **`interrupt()` 是抛异常中断** | 节点末尾的 `return {...}` **不会执行**。判断"停在哪"看 `graph.get_state(config).next` |
| **路由信号和业务标识不能共用一个字段** | 共用会导致"批准结果记到哨兵头上 → hub 判没批 → **无限弹同一个审批**" |
| **mock 生成的"计划"必然语义非法** | 它不知道 `depends_on` 要指向别的 step_id。所以 mock 模式下规划**总会走关键词兜底** —— 设计内降级，不是 bug |
| **`error_message` 有值 ≠ 任务失败** | 邮件被闸门拦下也写这个字段。前端要按终态挑措辞 |

## 7. 关键设计决策速查（面试用）

按"被问到什么"组织，每条都能展开成一两分钟的回答。

| 如果被问 | 回答的要点 |
| --- | --- |
| 为什么用 LangGraph | 需要**可中断、可恢复、可观测**的图执行。`interrupt()` + checkpointer 让"停下等人确认再续跑"变成框架能力而不是手写状态机。节点写成 `make_xxx_node(ctx)` 工厂，依赖在构图时确定 → 单测能直接调节点，不依赖 LangGraph 的函数签名内省 |
| 怎么防止模型乱来 | ① 计划**代码校验**（环/重复/未知依赖/无入口）；② 阈值判定不过模型；③ 工具网关 权限+限流+熔断；④ 对外动作强制 HITL；⑤ **用户权限 ∩ Agent 权限集**（这条件码是唯一真正防住越权的地方） |
| 为什么不用 Celery | 这一阶段目标是"把链路跑通、把数据落库"。任务状态本来就在数据库和 checkpoint 里，不依赖进程内存。但**这一步迟早要做**，见 §5 P1 |
| 为什么向量库用 Qdrant 不用 Milvus | 见 `docs/10` §1。一句话：**Milvus 最小部署要 etcd + MinIO，它的强项在上亿向量；而 etcd 或 MinIO 挂掉会让 RAG 整个不可用，这两件事和检索质量毫无关系**。选型跟着规模走 |
| 为什么写 `VectorStore` 抽象 | 三个**具体**理由：① 单测不能依赖外部服务；② "测试过 ≠ 生产能用"要用真组件验证 → 双后端契约测试**第一次运行就抓到了真 bug**；③ 切分/BM25/重排与存储无关 |
| 权限码为什么写在代码里 | 权限码和接口一一对应，接口变了权限就要变 → 必须跟代码走版本控制。角色和授权是**业务决策** → 放数据库。混合做法：码在代码、同步进库、角色授权只在**角色首次创建**时写入 |
| 为什么 token 里不放权限 | 放进去就不用每次查库，但**管理员撤权后要等 token 过期才生效**（最长 30 分钟）。审批发信这种动作不能接受这个窗口。所以 token 只放身份，权限每次现算 |
| 为什么 refresh token 要入库 | 企业必须能"**立刻踢下线**"（离职/设备丢失/异常登录）。纯 JWT 只能等过期。入库的是**哈希**，且每次刷新轮换 + 重放检测 |
| 密码为什么用 argon2id | ① 内存硬，抗 GPU 爆破；② **bcrypt 有 72 字节静默截断**，中文密码按 UTF-8 算 24 个字就到上限，超出部分被丢掉 → "前 72 字节相同的两个不同密码都能登录" |
| "零 Docker 也能跑"怎么做到的 | 依赖全部可插拔：MySQL↔SQLite、Redis↔内存/SQLite、Qdrant↔内存实现、模型↔mock。**降级只在安全的地方做**（限流器降级 = "没拦住"，可接受；向量库降级 = 索引变空，Agent 会把"空"当事实告诉用户，**绝不做**） |
| 为什么邮件默认发不出去 | 四个默认值全选"更安全的那个"：总开关关、dry_run 开、白名单空（空=禁发）、黑名单优先。**漏配的后果必须是"发不出去"，不能是"能发给任何人"** |

### 8.4 角色与权限速查

| 角色 | 能做什么 | **不能**做什么 |
| --- | --- | --- |
| `admin` | 全部 | — |
| `ops_manager` 运营主管 | 发起 + **审批** + 发信 | — |
| `operator` 运营专员 | 发起任务、生成报表 | **不能审批、不能发信** |
| `analyst` 数据分析 | 发起任务、导出报表 | 不能审批 |
| `viewer` 只读 | 只能看 | 不能发起任何任务 |

> **`operator` 没有 `task:approve` 是刻意的**：
> 能发起和能批准必须是两个人，否则人工闸口退化成"点一下就过"的形式主义。
> 这是 RBAC 在这个系统里存在的**唯一实际理由**。

## 10. 最后

**这个项目现在处于"能演示、能讲、但还不能对外暴露"的状态。**

三道门槛，按重要性排：

1. **任务队列**（P0-1）—— 现在重启就丢任务、多 worker 会重复跑。这是"能演示"和"能上线"之间最硬的一条线。
2. **JWT secret**（P0-3）—— 没配就每次重启把所有人登出。
3. **前端视觉**（P2-15）—— 等参考图。

前两条加起来大约是**半天到一天**的工作量，做完就可以在一个受控环境里真的用起来。

再往后（评测集、客服 Agent、混合检索）是"从能用到好用"的部分 ——
而 `docs/10` 里已经指出：**下一步第一优先级是建评测集，不是继续调参**，
因为没有评测集，"检索质量变好了"这句话是不可验证的。

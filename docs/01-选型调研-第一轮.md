# 办公 Agent 选型调研（第一轮）

> 调研时间：2026-09-11　状态：待决策

## 一、需求基线（已确认）

| 维度 | 结论 |
| --- | --- |
| 产品形态 | Web 应用（前后端分离） |
| 技术栈 | Python 后端 + React 前端 |
| 模型接入 | 国产优先（DeepSeek / 通义 / 智谱 / Kimi） |
| 部署 | 内网私有化 + 多用户 + 权限管理 |
| 交付深度 | 先对比选型，再动手改造 |

需要覆盖的办公场景：
1. 文档处理：Word / Excel / PPT 自动生成与改写
2. 邮件：自动撰写、分类、回复、总结
3. 会议：录音转写 + 纪要 + 待办提取
4. 知识库问答（企业文档 RAG）
5. 数据分析：上传 Excel 自动分析出图表 / 报告
6. 日程与任务管理（日历、提醒、待办）
7. 自动化工作流（多步骤、多工具编排）
8. 网页操作自动化（填表、抓资料、发帖）

## 二、候选项目对比

| 项目 | Stars | 后端 | 前端 | 许可证 | 匹配度 | 主要缺口 |
| --- | --- | --- | --- | --- | --- | --- |
| [Dify](https://github.com/langgenius/dify) | 155.4k | **Python** 46% | **React/Next.js** TS 50% | Dify 开源协议（Apache 2.0 + 附加条款） | ★★★★★ | 邮件 / 会议 / 日程非原生功能 |
| [FastGPT](https://github.com/labring/FastGPT) | 29.6k | TypeScript + Rust | Next.js | FastGPT 开源协议（Apache 2.0 + 附加条款） | ★★★★ | 栈不符（非 Python） |
| [Coze Studio](https://github.com/coze-dev/coze-studio) | 21.6k | **Go** | React + TS | **Apache-2.0** | ★★★ | 栈不符；社区版迭代放缓（最近 release 距今 7 个月） |
| [RAGFlow](https://github.com/infiniflow/ragflow) | 90.5k | Python + Go | React | Apache-2.0 | ★★ | 是 RAG 引擎，不是办公 Agent 产品；依赖重 |
| [Kortix / Suna](https://github.com/kortix-ai/suna) | 20.2k | TypeScript | React | **Elastic License 2.0** | ★★ | 栈不符；非真开源；依赖云沙箱，私有化改造重 |

### 各项目要点

**Dify**
- 能力：可视化工作流画布、RAG 管道、Agent（Function Calling / ReAct）、模型管理（数百个 provider，任意 OpenAI 兼容接口）、插件市场、LLMOps、BaaS API。
- 优势：技术栈与需求完全一致；生态最大（1464 位贡献者）；中文文档完整；DeepSeek 等在插件/Provider 列表内；自带 API/SDK 方便做自己的前台。
- 缺口：邮件、会议转写、日程需要自己写插件或工作流节点。

**FastGPT**
- 能力：知识库（TXT/MD/HTML/PDF/Docx/PPTX/CSV/XLSX、URL、CSV 批量导入）、混合检索 + 重排、Agent Skill 编排、对话工作流 / 插件工作流（含基础 RPA 节点）、双向 MCP、应用评测、免登录分享、iframe 嵌入、对话记录标注。
- 优势：国产模型开箱体验最好；RAG 与编排最"接地气"；RPA 节点可直接做网页自动化。
- 缺口：非 Python 栈；产品通用性不如 Dify。

**Coze Studio**
- 能力：模型服务、Agent 构建/发布、应用、工作流、插件、知识库、数据库、Prompt、OpenAPI + Chat SDK；微服务 + DDD 架构。
- 优势：Apache-2.0 最干净，改造自由度最高；产品形态对标 Coze，最接近成品。
- 风险：Go 技术栈；社区版更新几乎停滞；官方明确提示公网部署存在注册开放、代码节点沙箱、SSRF 等安全风险。

**RAGFlow**
- 优势：deepdoc 深度文档解析业界领先；模板化切分；带引用的可溯源回答；Agentic Workflow + MCP + 代码执行器；支持飞书/Discord/Telegram 等渠道；已支持 DeepSeek v4。
- 缺口：定位是 RAG 引擎，办公 Agent 只是附带；依赖 ES/Infinity + MySQL + MinIO + Redis，官方要求 16GB 内存 / 50GB 磁盘起。

**Kortix（原 Suna）**
- 优势：产品形态最接近"办公 Agent"——每会话独立沙箱、浏览器操作、产出报告/PPT、Slack 渠道、cron/webhook 触发器、成员/角色/权限、审计日志、密钥管理、3000+ 应用连接器。
- 缺口：全栈 TypeScript（94.5%）；Elastic License 2.0 禁止对外提供托管服务；强依赖云沙箱编排，私有化改造工作量大。

## 三、两个关键结论

### 结论 1：没有现成项目能开箱覆盖全部 8 个场景
现实路径是：选一个**底座**承载「工作流 / RAG / 模型管理 / 多用户」，再自行叠加办公垂直场景。

### 结论 2：许可证陷阱（与"私有化多用户"直接相关）
| 协议 | 允许 | 禁止 / 需授权 |
| --- | --- | --- |
| Dify | 商用、作为后台服务、企业内部应用开发平台 | **多租户环境**需书面授权（协议定义：1 个 workspace = 1 个租户）；不得移除或修改 `web/` 前端的 LOGO 与版权信息 |
| FastGPT | 商用、作为后台服务、交付给企业 | 与 FastGPT 类似的**多租户 SaaS** 需商业授权；不得移除控制台的 LOGO 与版权信息；交互设计有外观专利 |
| Coze Studio | Apache-2.0，商用、闭源改造均无额外限制 | —— |
| RAGFlow | Apache-2.0 | —— |
| Kortix / Suna | 自托管内部使用 | 不得作为托管 / 管理服务提供给第三方；不得绕过 license key |

> 区分两种"多用户"：
> - **单租户多用户**（一个公司/团队一个 workspace，内部多人分工）→ Dify / FastGPT 均允许，无需授权。
> - **多租户**（每个客户一套独立 workspace，对外运营）→ Dify / FastGPT 均需商业授权。

## 四、推荐方案

**首选：Dify 作为底座**

理由：
1. 技术栈是候选里唯一完全匹配的（Python + React），二次开发成本最低；
2. 工作流画布 + RAG + Agent + 插件市场（含 Gmail / Outlook / Slack 等）+ OpenAI 兼容层，DeepSeek / 通义 / 智谱 / Kimi 均可直接接入；
3. 社区体量最大（155.4k star / 1464 contributors），踩坑成本最低；
4. 自带 API 与 SDK，便于自研独立的办公工作台前端。

建议组合：
- **Dify 当底座**：负责模型接入、知识库、工作流编排、多用户与权限；
- **另起一个 React 办公工作台**（走 Dify API 调用），而不是直接改 Dify 的 `web/`，以避免触发 LOGO 与版权条款；
- **办公垂直功能自研 Dify 插件 / 工作流节点**：
  - 邮件 → IMAP/SMTP 插件
  - 会议 → Whisper / FunASR 转写后接纪要 + 待办抽取工作流
  - 日程 → CalDAV / 飞书日历插件
  - 数据分析 → 代码执行节点 + 图表渲染
  - 网页自动化 → Playwright（脚本节点 / 插件）

**备选 A：FastGPT**
若更看重「国产模型 + 知识库问答 + 可视化编排开箱即用」，且能接受 TypeScript + Rust 栈。

**备选 B：Coze Studio**
若未来要做成对外商业产品，Apache-2.0 授权最干净，但要接受 Go 后端栈与较慢的社区迭代节奏。

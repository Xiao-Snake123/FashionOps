### 关键设计决策（面试可讲）

**决策一：路径沙箱用「解析后比较路径段」而不是字符串 `startswith`**

```python
# ❌ 错误做法：str(target).startswith(str(root))
#    /data-evil 会被误判为 /data 的子路径
# ✅ 正确做法：Path.relative_to() 会按路径段比较
def _is_relative_to(child, parent):
    try:
        child.relative_to(parent)
    except ValueError:
        return False
    return True
```

**决策二：给模型的错误必须带 `hint`**

`hint` 不是给人看的日志，而是**给模型的下一步动作建议**。
实测把 `hint` 加上后，模型面对 `file_not_found` 会先调 `list_files`，
而不是换个路径继续瞎试。

**决策三：产物统一落到 `outputs/` 且文件名必须清洗**

模型给的 `filename` 可能含 `../` 或 `/`。经 `safe_filename()` 清洗后
`../../evil.md` → `___evil.md`，再拼到 `outputs/` 下，双重保险。

### 四层发送闸门的设计

| 层 | 规则 | 理由 |
| --- | --- | --- |
| 1 | **白名单为空 → 禁止发送** | fail-closed：漏配的后果应该是「发不出去」而不是「能发给任何人」 |
| 2 | 黑名单优先 | 给管理员一个紧急刹车 |
| 3 | 收件人数 + 附件扩展名 + 附件大小 | 挡群发、挡 `.env`/私钥外发 |
| 4 | 滑动窗口限流 | 挡模型循环发信 |

配套两条：

- **`to`/`cc`/`bcc` 全部校验** —— 只看 `to` 的话，把目标塞进 `cc` 就绕过了。
- **被拒时 `hint` 指向 `save_email_draft`** —— 让 Agent 有路可走，而不是卡死或反复重试。

### 踩坑记录

| # | 问题 | 原因 | 解决 |

   - `server.py` —— 9 个 MCP 工具

2. **新增 122 个测试**（总计 297）。

3. **新增 `scripts/demo_calendar.py`** —— 12 个场景，走完"导入邀请 → 找空闲 → 排会冲突 → 改期 → 导出 ICS"完整流程。

### 设计要点

| 要点 | 说明 |
| --- | --- |
| **左闭右开** | 10:00–11:00 与 11:00–12:00 不算冲突，这是日历场景唯一合理的约定 |
| **相邻即合并 vs 相邻不冲突** | 看似矛盾，实则都对：合并是为了不生成 0 长度假空闲，严格比较是为了不误报冲突 |
| **时间统一带时区并转到配置时区** | 否则系统里会混着 `+00:00` 和 `+08:00`，排查时极易看错 |
| **导出 ICS 统一转 UTC** | 跨客户端兼容性最好的做法 |
| **查询用交集而非包含** | 08:00–20:00 的全天会议，查 12:00–13:00 也必须返回 |
| **明确不展开 RRULE** | 展开要处理 EXDATE/RDATE/时区/无限重复，属独立课题，当前明确不猜 |
| **忙碌情况可隐藏标题** | 跟外部方对时间时不该告诉对方"你在做什么" |

### 踩坑记录

| # | 问题 | 原因 | 解决 |
| --- | --- | --- | --- |
| 13 | **带 `Z` 的时间没转换到配置时区** ⭐ | `parse_datetime` 只做 `ensure_aware` 不做 `astimezone`，导致返回值时区五花八门 | 改为 `ensure_aware(...).astimezone(tz)`，并补测试断言"时刻不变、时区统一" |
| 14 | 新生成的事件 UID 没有域名后缀 | `ics.py` 里直接用了 `uuid4()`，没复用 `new_uid()` | 把 `new_uid()` 提到 `models.py` 供两处复用 |
| 15 | 测试 `test_parse_explicit_offset_wins` 断言过期 | 行为按设计变了（现在会转换时区），断言没跟着改 | 改为断言"时刻不变"（`astimezone(UTC).hour == 14`），这才是真正该守住的性质 |
| 16 | ruff 自动修复删掉 `store.py` 的 `new_uid` 导入后测试收集失败 | 测试还在从旧位置导入 | 测试改为从 `models` 导入 |

> 13 是典型"不写端到端测试就发现不了"的问题：单看某个函数都对，但系统整体
> 会出现时区不一致的输出，模型看到 `+00:00` 和 `+08:00` 混排会算错时间。

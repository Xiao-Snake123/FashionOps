# 简历项目候选：可二次开发的 Agent 开源项目

> 目标：Agent 开发工程师岗位　　标准：**面试可讲的技术深度 × 上手速度**
> 调研时间：2026-09-11

## 一、筛选标准（为什么换了一批项目）

简历项目的关键是**你改了什么、为什么这么改、效果数据**。
所以不能选"部署一个平台就行"的项目（那只能讲运维），要选**你能读懂并改动其 Agent 内核**的项目。

四条硬标准：
1. **Python 为主** —— 国内 Agent 岗绝大多数要 Python，且你要能读源码
2. **许可证宽松**（MIT / Apache-2.0）—— 要能改名改成自己的项目
3. **代码量可控 + 有清晰扩展点** —— 时间有限，必须能快速插进去加功能
4. **技术点对口面试题库** —— LangGraph / 多智能体 / RAG / MCP / 记忆 / 沙箱 / 评估

### 它自带的技术点（几乎覆盖 Agent 岗面试清单）

| 面试常问 | DeerFlow 里的对应实现 |
| --- | --- |
| 多智能体协作 | LangGraph 编排的 lead agent + 动态派生子 agent，子 agent 上下文隔离 |
| 上下文工程 | 自动摘要压缩、中间结果落盘、`/compact` 手动压缩、上下文窗口仪表 |
| 工具调用 / MCP | 内置 MCP server 接入（HTTP/SSE/stdio），工具前缀防冲突，延迟加载 + 自动提升 |
| 长期记忆 | DeerMem 默认后端 + mem0 / honcho / OpenViking 可选，事实按 scope 分级写入，混合淘汰策略 |
| RAG | 只读 LightRAG 检索集成 |
| 沙箱与安全 | 每任务独立文件系统（uploads / workspace / outputs），Docker / K8s / E2B 三种隔离，网络出口白名单 |
| 浏览器自动化 | Playwright 工具组，元素 `[ref]` 标注 + 快照驱动，SSRF 防护 |
| 流式输出 | LangGraph SSE 协议、跨 worker 的 Redis stream bridge、断点续传 `Last-Event-ID` |
| 可观测性 | LangSmith / Langfuse / Monocle 三套 tracing 同时接入，trace id 贯穿全链路 |
| 权限体系 | 可插拔授权 Provider，按角色控制 tools / routes / models / skills / sandbox |
| 任务调度 | cron / interval / once 定时任务，跨实例租约与孤儿恢复 |
| IM 集成 | 飞书 / 钉钉 / 企业微信 / 微信 / Slack / Telegram / Discord |

### 二次开发切入点（这些都能写成简历亮点）

1. **把办公场景做成 Skill**
   它用 `SKILL.md` 定义能力模块，渐进加载。你可以写「会议纪要」「周报生成」「邮件起草」「合同审核」四个 skill —— 改造成本极低，但这就是你的产品功能。
2. **写一个 AgentMiddleware 扩展**
   用它的 extensions 机制注入自定义中间件，做**工具调用治理**（比如限制写文件、拦截敏感参数、加审计日志）。这是"我改了内核"级别的证据。
3. **换模型 / 加国产模型适配**
   DeepSeek、Kimi、豆包已是官方推荐；你可以加通义/智谱的适配层，并做**多模型路由**（按任务复杂度选模型，降本）。
4. **建评估集，跑量化指标**
   自己造 20-50 条办公任务，测成功率 / 平均步数 / 延迟 / token 成本，做改进前后对比。**这是最加分的一项**——大多数候选人给不出数字。
5. **做企业级增强**
   多租户隔离、操作审计、配额限流。它已有 RBAC 骨架，你在上面补。

### 风险
- 代码量大（网关、运行时、沙箱、前端分离），刚开始读会晕 → 建议从 `backend/packages/harness/deerflow/` 和 `backend/docs/` 入手
- 定位偏"深度研究 / 通用超级 Agent"，办公场景要你自己用 skill 补

## 三、备选 A：OpenManus —— `FoundationAgents/OpenManus` ⭐ 58.3k

| 项 | 内容 |
| --- | --- |
| 语言 | **Python 97.7%** |
| 许可证 | **MIT** |
| 活跃度 | 一般（最后提交 1 个月前，最后 release 是 1 年前） |

**优点**：代码量小、结构简单（作者说 3 小时原型），**最容易读透**。默认集成 browser-use CLI 3.0 作为 MCP server，自带 DataAnalysis Agent（数据分析 + 可视化，正好对口你的场景）。国内认可度高（MetaGPT 团队出身）。

**缺点**：正因为简单，**能讲的技术深度有限**。想上简历得自己补一大块（加 Web 前端、加记忆、加评估），工作量大。
**适合**：你只剩 2-3 周，要先做出一个能演示的东西。

## 六、推荐路线

### 路线 1（推荐）：DeerFlow 2.0 深度二次开发
```
DeerFlow 底座（Agent 内核 + 网关 + 前端）
  ├─ 加 4 个办公 Skill（会议纪要 / 周报 / 邮件 / 文档审核）
  ├─ 加 1 个自研 Middleware（工具调用治理 + 审计）
  ├─ 加国产模型适配 + 多模型路由（降本）
  ├─ 加评估集与指标看板（成功率 / 延迟 / 成本）
  └─ 改品牌 / UI 成自己的产品名
```
**产出**：一个能跑的"企业办公 Agent 平台" + 一套量化指标 + 一份架构文档。
**面试可讲**：多智能体编排、上下文压缩策略、沙箱安全边界、流式架构、模型路由的 tradeoff。

### 路线 2（求快）：OpenManus + 自建 Web 层
```
OpenManus 内核（Agent loop）
  + FastAPI 后端包装
  + React 前端（对话 / 任务看板 / 文件产物）
  + 记忆模块 + 评估脚本
```
**产出更快，但要自己补的更多**，深度靠你后来加的东西撑。

## 七、写进简历的要点（很重要）

面试官看到「做了个办公 Agent」已经泛滥了，区分度来自这三样：

1. **架构图 + 你改的那一层**（不是"我部署了 X"）
   例：「在 DeerFlow 的 LangGraph 编排层新增 XMiddleware，实现工具级权限与审计」
2. **量化数据**
   例：「任务成功率从 62% → 84%；平均步数 11.3 → 7.8；单任务成本下降 41%」
3. **Tradeoff 说明**
   例：「子 Agent 并行能降延迟，但会增加 token 消耗，因此设置 max_concurrent=1 的降级策略」

> 现在就可以开始记录：每改一个点，存一份"改动前 vs 改动后"的数据。

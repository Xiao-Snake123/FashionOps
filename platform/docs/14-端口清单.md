# 端口清单

## 应用层（本项目进程）

| 端口 | 服务 | 默认？ | 改端口 |
|---|---|---|---|
| 3000 | 前端 Vite（React） | 默认起 | `start.ps1 -FrontendPort` |
| 8010 | 后端 FastAPI / uvicorn | 默认起 | `start.ps1 -BackendPort` |
| 8100 | MCP / SSE 服务 | 默认起 | `start.ps1 -McpPort` / `-NoMcp` |
| 8011 | DeerFlow sidecar | **默认不起** | `-WithDeerFlow` 才起 |

前端把 `/api` 与 `/health` 代理到后端（默认 `http://127.0.0.1:8010`，见
`frontend/vite.config.ts`）；后端换端口时用 `VITE_API_TARGET` 改。

## 端口冲突与避让

本机另有一个**股票系统**，两边默认端口撞了：

| 端口 | 股票系统 | platform（改后） |
|---|---|---|
| 8000 | FastAPI 后端 / WebUI（`main.py --webui-only`） | ~~8000~~ → **8010** |
| 8001 | Java Spring Boot（`dsa-server.jar`） | ~~8001~~ → **8011** |
| 5173 | Vite dev server（`apps/dsa-web`） | 3000（不冲突） |
| 动态 | Electron 桌面端（从 8000 起自动选空闲端口） | — |

**处理原则**：股票系统的端口不动，让 platform 整体挪到 **8010 段**。

选 8010 而不是 8002/8003，是因为 Electron 从 8000 起**往上扫空闲端口**，
8010+ 更不容易被它占先。Electron 本身会自动避开已占用端口，所以它不是真冲突。

**改端口必须同时改这 4 处**（漏一处就会出现"前端连不上后端"）：

1. `deploy/scripts/start.ps1` —— `-BackendPort` 默认值 / DeerFlow 端口
2. `deploy/scripts/stop.ps1` —— 同上两个默认值
3. `frontend/vite.config.ts` —— 代理目标 `VITE_API_TARGET` 默认值
4. `backend/fashionops/config.py` —— `deerflow_base_url` 默认值
   （外加 `..\deerflow\run_gateway.cmd` 里的 `--port`）

改完要 `.\stop.ps1` 再 `.\start.ps1` —— 已开着的前端还指向旧端口。

# 服装电商多 Agent 运营中台 —— 交接与上手文档

> 适用对象：要接手 / 在另一台电脑上继续开发本项目的人。
> 仓库：`https://github.com/Xiao-Snake123/FashionOps.git`，默认分支 `master`。
> 配套：`platform/README.md`（详细运行手册）、`platform/docs/12~14`（设计 / 数据模型 / 端口）。

## 1. 这是什么

一句话：运营说一句「帮我选 3 款秋季女装并出报表发给运营组」，系统自己拆成有序步骤、逐步执行，涉及对外发信的步骤**停下来等人点确认**，全程可追踪、可干预、可评测。

- 当前主要产出是 `platform/`（服装电商多 Agent 运营中台）。
- 同仓库还有 `mcp-servers/`（办公能力 MCP 服务器：文档 / 邮件 / 日历），是**独立可交付**项目，**目前与 platform 没有打通**；接手 platform 可以暂时忽略它。
- 仓库根目录叫 `Work agent`（带空格），所有路径命令都要带引号。

## 2. 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | FastAPI + uvicorn + SQLAlchemy 2.0 + Pydantic v2 |
| 关系库 | MySQL 8.0（29 张表，Alembic 管理迁移） |
| 缓存 / 限流 / 熔断 | Redis 8.x |
| 向量库 | Qdrant 1.x（客服 RAG 检索） |
| 执行编排 | **自研**：一个 Agent + 显式 todo 列表（不用 DAG / LangGraph） |
| 工具协议 | MCP（stdio + SSE 双传输）—— 对外暴露平台工具，也反向消费外部 MCP |
| 可选编排 | DeerFlow（LangGraph）sidecar，**默认不启用** |
| 前端 | React + Vite + ECharts |
| 模型 | OpenAI 兼容接口，默认 `mock`（**不填 Key 也能跑通全链路**） |

## 5. 在另一台电脑上拉取并开发（重点）

> 部署脚本是 **Windows / PowerShell**，以下步骤按 Windows 写；非 Windows 见末尾"其他系统"。

```bash
# 1) 克隆（仓库根目录名带空格，注意引号；私有库需 GitHub 登录 / PAT / SSH 权限）
git clone https://github.com/Xiao-Snake123/FashionOps.git
cd "Work agent"

# 2) 进项目目录
cd platform

# 3) Python 依赖 —— .venv / node_modules / .env 都不进仓库，必须重建
python -m venv .venv
.venv\Scripts\activate
uv sync --all-extras            # 推荐；没有 uv 就：pip install -e ".[dev]"

# 4) 前端依赖
cd frontend && npm install && cd ..

# 5) 起依赖服务 Redis + Qdrant（或自己用 Docker 起，然后 start.ps1 -SkipData）
cd deploy\scripts
.\services.ps1 start

# 6) 初始化 MySQL（建库+账号+写 .env，会交互问 root 密码；
#    也可手动 cp .env.example .env 填好 DB 连接）
.\init-mysql.ps1
cd ..\..

# 7) 建表 + 灌演示数据
.venv\Scripts\fashionops-db.exe init
.venv\Scripts\fashionops-seed.exe

# 8) 一键起全部
cd deploy\scripts
.\start.ps1
```

起好后访问 http://localhost:3000，演示账号同上。

**不会跟着跑的东西（都在 .gitignore，勿提交）：**

- `.venv/`：每台机器各自建。
- `frontend/node_modules/`：`npm install` 生成。
- `platform/.env`：真实凭据（DB 密码 / 邮箱授权码 / 模型 Key）只在这里；`.env.example` 是模板。
- 前端 `dist/`、后端 `__pycache__` 等。

**其他系统（Linux / macOS）：** 没有 `.ps1`，手动来：

```bash
# 依赖服务
docker run -d -p 6379:6379 redis:8
docker run -d -p 6333:6333 -p 6334:6334 qdrant/qdrant
# 后端
.venv/bin/uvicorn fashionops.api.main:app --host 127.0.0.1 --port 8010 &
# 前端
cd frontend && npm run dev          # http://localhost:3000
# MCP（可选）
.venv/bin/uvicorn fashionops.mcp.server:create_sse_app --factory --port 8100 &
```

MySQL 用你自己的实例，`platform/.env` 里 `FASHIONOPS_DB_*` 指过去，再 `fashionops-db init` + `fashionops-seed`。

## 6. 架构与关键决策（接手前必读）

- **编排是自研的，不是 LangGraph。** `workplan.py` 按关键词把一句话拆成有序步骤（命中 0~1 类意图→单步直接做；≥2 类→多步）；`loop.py` 逐步执行，每步按 `kind` 裁剪工具目录；`recorder.py` 旁路记账（事件流 + agent_runs + 任务主表）。**刻意删掉了**：模型出 DAG、图校验与环检测、hub 路由、9 个专用 Agent 节点、LangGraph checkpoint。理由见 `docs/12-AI协作交接.md`。
- **DeerFlow 只是可选的第二种编排后端（sidecar，默认不起）。** 链路：平台 → DeerFlow(:8011) → 平台 MCP(:8100) → 平台工具。外部 Agent 调写操作走审批闸口，工具不会被执行，只回 `needs_approval`。
- **不可撤销的动作必须有闸口。** 发信前落审批单 + 停下来等人；批准时执行的是**当时存下来的那份参数**，人和系统看同一份内容。`tools/mail.py` 是 fail-closed：白名单为空谁都发不出去。
- **算数交给代码，表达交给模型。** 打分、阈值、拆步骤是可复现纯函数；模型只负责理解和写结论。
- **基准区间 / 状态机由后端给，前端不写死。** 看板类目退货率的行业基准带、工单状态机枚举都来自后端。
- **假数据必须埋异常。** 库存告急、ROI 暴跌、纠纷工单、失败运行——不然熔断 / 转人工这些分支永远演示不出来。

## 7. 后端接口地图（前端 / 接 MCP 用）

| 前缀 | 文件 | 内容 |
| --- | --- | --- |
| `/api/v1/business` | `business.py` | 商品 / 工单 / 广告 / 退货率等**只读**查询 |
| `/api/v1/actions` | `actions.py` | **写操作**：广告批准 / 驳回 / 止损 / 改预算；邮件闸门策略读取 / 改白名单 / 演练转真发 / 重发（本轮新增） |
| `/api/v1/service` | `service.py` | 客服工单派单 / 人工进度 / 阶段枚举 |
| `/api/v1/admin` | `admin.py` | 账号分级授权、异常登录审计 `/security/logins` |
| `/api/v1/tasks` | `tasks.py` | 任务详情 + 关联单据 `related_docs` |
| MCP | `mcp/server.py` | 把上面这些工具以 MCP/SSE(:8100) 暴露给外部 Agent |

> 写操作单开一个 router（`actions.py`）而非塞进只读的 `business.py`：review 时"系统里哪些接口会改状态"有唯一答案。

## 10. 踩过的坑 / 须知

- **端口刻意避开 8000 / 8001**：本机另一个股票系统占着（FastAPI/WebUI 占 8000、Java 占 8001）。换端口用 `start.ps1 -BackendPort 8020`，前端会自动跟着改 `VITE_API_TARGET`。完整清单见 `docs/14-端口清单.md`。
- **前端只能用 `http://localhost:3000`**（走 IPv6 `::1`），`127.0.0.1` 连不上。
- **`start.ps1` 按命令行特征（不是端口）判断进程归属**，避免被别的 python 程序骗过而"假启动"。
- **seed 时间锚点已改为"今天"**：之前写死 `2026-09-11`，随日历推移近 30 天窗口会变空、页面全显示 0 且不报错，最难查。重灌数据用 `fashionops-seed`。
- **提交范围**：仓库根目录有一批非项目文件（`.playwright-cli/`、`.pw-profile/`、各 `*.yaml` 测试录制、`工作记录/`、`新-前端…md`），**不要提交**。推荐暂存方式：`git add platform/ README.md docs/`。
- **pre-commit 钩子扫硬编码密钥**：真实凭据只进 `platform/.env`，别写进代码。
- **`docs/09`、`docs/11`（根目录）是权威现状文档但部分过期**（端口、测试数），以本文 + `platform/README.md` 为准。
